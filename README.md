# 社区灭蚊消杀预约与积水点复查服务

## 原始需求

> 开发社区灭蚊消杀预约与积水点复查服务，可采用 Go、PostgreSQL 和 Redis。居民、物业或网格员上报蚊虫密集、楼顶积水、地下室潮湿、绿化带积水、垃圾桶异味或儿童被叮咬后，服务记录位置、照片、时间、周边人群和是否有宠物。街道按小区、积水点类型、近期降雨、投诉密度、消杀队排班和药剂库存生成派单。消杀人员到场后，记录药剂、浓度、喷洒区域、警示牌、居民告知、宠物避让和是否发现新的积水点。若居民拒绝入户、儿童活动区需要避开时段、宠物主人投诉、药剂不足、积水由物业设施造成或复查仍有幼虫，服务要把居民、物业、消杀队、街道和卫生监督放在同一工单中处理。复查结果、药剂消耗、投诉下降和整改责任进入街道考核。服务还要覆盖楼顶水箱、废旧轮胎、地下车库、绿化灌木、雨水井和建筑工地等不同蚊虫来源。消杀后的复查、居民告知和物业整改必须连接起来，街道才能判断投诉是否真正下降。对登革热等重点风险期，服务要提高复查频次，自动生成重点积水点清单，并让街道看到每个小区从投诉到整改的闭环进度。

## 追加需求：儿童活动区错峰消杀

> 增加儿童活动区错峰消杀。幼儿园旁绿化带需要消杀时，服务根据儿童活动时间、风向、药剂安全间隔和园方联系人安排作业。作业完成后，警示撤除和园方确认进入工单。园方确认后，居民端会看到安全间隔和儿童活动恢复时间。作业前提醒会推送给幼儿园、家长群和附近居民。作业提醒会标明避让时段和联系人，并保留送达状态。

**范围门禁（隐私与归属校验）**：
- `GET /api/child-zone-plans/{id}`：居民/物业/网格员仅本小区；居民仅可见**园方已确认**计划的公开字段（安全间隔、恢复时间、避让时段），不返回园方联系电话与提醒明细（未确认计划对居民为 404）；园方联系人仅可读绑定活动区的计划。
- `POST /api/child-zone-plans/{id}/reminders/{rid}/deliver`：仅**对应幼儿园联系人、街道、实际作业消杀队**（关联工单所属队）可更新送达状态，其余角色 403 且数据不变。
- `POST /api/child-zone-plans/{id}/confirm`：活动区**必须已绑定园方联系人账号**且与当前登录园方一致；未绑定（409）或非绑定账号（403）均返回 4xx，计划状态、确认字段、居民通知与工单日志保持不变。
- 居民的计划列表同样只含本小区已确认计划，且隐去园方联系电话。

## 追加需求：宠物误触投诉处理

> 增加宠物误触投诉处理。宠物主人反馈喷药后宠物不适时，服务关联药剂、喷洒区域、警示时间和主人行走路线。卫生监督可判断是否需要回访、赔付或调整后续告知方式。投诉处理会记录宠物就医凭证、药剂说明和后续告知调整。后续告知方式调整后，同类宠物投诉会继续跟踪是否下降。跟踪结果会进入小区消杀档案和下次计划。

实现要点：
- 居民提交宠物投诉时自动关联本小区最近一次消杀记录（快照药剂、喷洒区域、警示时间），并记录主人行走路线与宠物就医凭证链接；未闭环工单会同步生成「宠物主人投诉」异常进入五方协同。
- 卫生监督/街道办结：判断是否回访、赔付，记录药剂说明与后续告知方式调整。
- 告知调整后，系统按调整前后窗口（日均）跟踪同类宠物投诉是否下降（`/api/pet-complaints/tracking`）。
- 跟踪结果进入小区消杀档案（`/api/communities/{id}/archive`：消杀统计、药剂消耗、投诉与告知调整、跟踪结论）并展示在派单中心，作为下次计划参考。

## 技术栈与架构

- **后端**：Go 1.23（标准库 `net/http` 路由，lib/pq，go-redis，bcrypt），单二进制，前端静态文件 `go:embed` 内嵌
- **数据库**：PostgreSQL 16（工单、上报、积水点、消杀/复查/整改/异常等全部业务数据）
- **缓存**：Redis 7（登录会话、投诉密度缓存、重点风险期缓存）
- **部署**：多阶段 Dockerfile（非 root 用户 + HEALTHCHECK）+ docker compose（app + db + redis）

```
浏览器 ──> app:8080 (Go) ──> db:5432 (PostgreSQL)
                        ──> redis:6379 (Redis)
```

## 一键启动

```bash
cp .env.example .env        # 按需修改端口与密码
docker compose up -d        # 构建并启动 app + postgres + redis
docker compose ps           # 等待三个服务全部 healthy
```

- 浏览器访问：`http://localhost:${CC_PUBLISH_PORT}`
- 健康检查：`curl http://localhost:${CC_PUBLISH_PORT}/healthz`
- 停止并释放资源：`docker compose down`（加 `-v` 同时清空数据）

> 验证方式 = 在宿主机执行 `docker compose up -d`，待服务 healthy 后，用浏览器或接口走通下方"关键业务流"。数据库与 Redis 不发布宿主端口，仅 compose 内部网络互访。

> 也可运行随附的接口级自检脚本（覆盖 43 项断言：六角色登录、上报、派单评分、消杀扣库存、复查、幼虫升级五方协同、整改核验、告知、自动闭环、看板、权限边界）：

## 关键业务流（建议按序体验）

1. **上报**：居民 `resident` 登录 →「上报问题」提交（蚊虫密集/楼顶积水/儿童被叮咬等，可填照片链接、周边人群、是否有宠物）。积水类上报自动生成积水点。
2. **派单**：街道 `street` →「派单中心」查看评分（类型权重 + 投诉密度 + 近期降雨 + 重点积水点 + 风险期 ×1.5）→「生成派单」，系统按消杀队排班剩余产能自动指派，药剂预估不足自动生成「药剂不足」异常。
3. **消杀**：消杀 `operator` →「我的工单」→ 详情 →「到场开工」→ 提交消杀记录（药剂、浓度、用量、喷洒区域、警示牌、居民告知、宠物避让、新积水点）。库存实时扣减，低于安全库存自动触发「药剂不足」异常。
4. **复查**：工单进入「待复查」（重点风险期 3 天、平时 7 天）。`operator`/`grid`/`supervisor` 提交复查：通过 → 满足闭环条件自动闭环；**仍有幼虫 → 自动生成「复查仍有幼虫」异常并拉通五方协同**。
5. **异常协同**：工单详情内可上报 居民拒绝入户 / 儿童活动区时段 / 宠物主人投诉 / 药剂不足 / 积水由物业设施造成 / 仍有幼虫，居民、物业、消杀队、街道、卫生监督进入同一工单时间线协同；街道/卫生监督登记解决结果。
6. **物业整改**：街道在工单内下发整改（责任物业、期限）→ 物业 `property`「整改任务」受理并完成 → 街道/卫生监督核验 → 核验通过回到待复查。
7. **居民告知**：街道/物业发布告知（工单关联或小区广播），居民端可见；**闭环条件 = 已消杀 + 复查通过 + 异常清零 + 整改核验 + 已告知**，缺一不可，街道才能确认闭环。
8. **考核与闭环看板**：街道「闭环看板」查看每小区 投诉→派单→消杀→复查→整改→闭环 进度与投诉下降率；「考核看板」按月输出复查通过率、药剂消耗、投诉下降、整改责任（小区 + 消杀队两个维度）。
9. **重点风险期**：街道「重点风险期」开启登革热防控期 → 复查频次提高（间隔天数可配）、派单优先级 ×1.5、「重点积水点」清单自动更新（曾发现幼虫 / 重点类型 / 投诉密集小区），覆盖楼顶水箱、废旧轮胎、地下车库、绿化灌木、雨水井、建筑工地等来源。
10. **儿童活动区错峰消杀**：街道「错峰消杀」登记儿童活动区（园方联系人、儿童活动时段、家长群）→ 新建错峰计划（作业时段 + 风向 + 药剂安全间隔；**与儿童活动时间冲突会被拒绝**）→ 创建即向幼儿园、家长群、附近居民推送提醒（标明避让时段与联系人，保留 待发送/已发送/已送达 状态）→ 消杀提交后计划自动转「已作业」→ 消杀队撤除警示（记入工单时间线）→ 园方联系人 `kindergarten` 登录确认（记入工单）→ 居民端在「儿童活动区」与「居民告知」看到安全间隔与儿童活动恢复时间。
11. **宠物误触投诉**：居民「宠物投诉」提交（症状、行走路线、就医凭证，自动关联最近消杀的药剂/区域/警示时间）→ 卫生监督「宠物投诉」办结（回访/赔付/药剂说明/后续告知调整）→ 跟踪面板按调整前后日均对比同类投诉是否下降 → 跟踪结果进入「小区档案」并显示在派单中心供下次计划参考。

## 主要接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 登录（Redis 会话 24h） |
| POST/GET | `/api/reports` | 上报提交 / 列表（按角色过滤） |
| GET/POST | `/api/water-points` | 积水点列表 / 登记 |
| GET | `/api/water-points/key-list` | 重点积水点清单（自动标记） |
| GET/POST | `/api/dispatch/preview` `/api/dispatch/generate` | 派单评分预览 / 生成派单 |
| GET | `/api/work-orders` `/api/work-orders/{id}` | 工单列表 / 详情（参与方+时间线+闭环条件） |
| POST | `/api/work-orders/{id}/assign` `/start` `/treatments` `/rechecks` `/issues` `/rectifications` `/close` | 工单全流程操作 |
| POST | `/api/rectifications/{id}/start` `/complete` `/verify` | 物业整改流转 |
| GET/POST | `/api/chemicals` `/api/chemicals/{id}/restock` | 药剂库存与补货 |
| GET/POST | `/api/risk-periods` `/{id}/activate` `/{id}/deactivate` | 重点风险期管理 |
| GET/POST | `/api/child-zones` | 儿童活动区（联系人/活动时段/家长群） |
| GET/POST | `/api/child-zone-plans` | 错峰消杀计划（错峰校验+自动生成三类提醒） |
| POST | `/api/child-zone-plans/{id}/send-reminders` `/reminders/{rid}/deliver` | 提醒发送与送达确认 |
| POST | `/api/child-zone-plans/{id}/remove-warning` `/confirm` | 警示撤除 / 园方确认（入工单+居民端通知） |
| GET/POST | `/api/pet-complaints` `/{id}/handle` `/{id}/vouchers` | 宠物误触投诉（关联药剂/区域/警示时间/路线，办结记录凭证/药剂说明/告知调整） |
| GET | `/api/pet-complaints/tracking` `/api/communities/{id}/archive` | 同类投诉下降跟踪 / 小区消杀档案 |
| GET | `/api/dashboard/closed-loop` `/assessment` `/complaint-trend` | 闭环看板 / 街道考核 / 投诉趋势 |

## 目录结构

├── db.go / redis.go        # PostgreSQL 建表迁移、Redis 连接
├── seed.go                 # 演示数据（幂等，仅空库注入）
├── auth.go                 # 登录/会话（Redis）
├── handlers_reports.go     # 上报、积水点、居民告知
├── handlers_dispatch.go    # 派单评分与生成、排班、药剂、降雨
├── handlers_orders.go      # 工单全流程（消杀/复查/异常/整改/闭环）
├── handlers_dashboard.go   # 风险期、闭环看板、考核、投诉趋势
├── static/                 # 前端 SPA（go:embed 内嵌）
├── Dockerfile              # 多阶段构建，非 root + HEALTHCHECK
├── docker-compose.yml      # app + postgres + redis
└── .env.example            # 环境变量样例
```
